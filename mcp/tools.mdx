The Found by AI MCP server exposes 17 tools your AI assistant can call mid-conversation. Sixteen are read-only queries against your live measurement data; one — `request_rescan` — triggers a fresh measurement that counts against your plan's on-demand allowance. All tools work with a personal token in the endpoint URL; read-only tools also work with scoped keys, which is useful for giving an agent access to a single domain without sharing your full account token.

<Note>
  **No account yet?** Point your assistant at the demo endpoint — `https://areyoufoundbyai.com/mcp/demo` — to explore all 17 tools against Found by AI's own live measurement data before you run your first scan. No token and no signup required. On the demo endpoint `request_rescan` returns a worked example of its response and queues nothing.
</Note>

## The 17 tools

### 1. `get_visibility(url)`

Returns your current AI Visibility Score and AI Readiness Score (each out of 100), the previous week's scores for comparison, the separate off-site Footprint score, and the dimension subscores — AI Citability, Brand Authority, Content E-E-A-T, Technical GEO, Schema & Structured Data, and Platform Optimization.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query (e.g. `https://example.com`) |

**Returns:** current and previous visibility score, current and previous readiness score, Footprint score, per-dimension subscores, weekly trend direction, and a `last_full_scan` timestamp.

---

### 2. `get_answers(url)`

Returns the verbatim answer each AI engine gave to each tracked buyer question, along with the web searches the engine ran before answering, the date and model used, how many samples named the business, and which competitors appeared in each answer.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain whose category to query |

**Returns:** array of question/engine/answer records, each with the exact engine response, pre-answer searches, sample count, named competitors, and whether the engine used live web search or model memory.

---

### 3. `get_cited_queries(url)`

Reverse lookup: name a competitor domain and receive the specific buyer questions where AI engines named that competitor instead of you. Use this to find the exact questions where your share-of-voice is weakest.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The competitor domain to look up |

**Returns:** array of buyer questions where the specified competitor was named, with engine-by-engine breakdown for each question.

---

### 4. `get_question_trajectories(url)`

Returns every tracked buyer question and a day-by-day history of how many of the seven engines named the given domain on each measured day. Use this to spot whether visibility on a specific question is rising, falling, or flat.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query |

**Returns:** array of questions, each with a time-series of named counts (out of 7) across all measurement dates.

---

### 5. `get_rivals(url)`

Returns the competitor names AI engines gave to buyers instead of the given domain in the latest scan, plus which questions each competitor appeared on and how often they have recurred across measurements.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query |

**Returns:** list of competitor names with question-level detail and recurrence data.

---

### 6. `get_share_of_voice(url)`

Returns the given domain's share of AI-answer mentions relative to the rivals the engines name in the same category, and shows how that share has moved over the tracked measurement window.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query |

**Returns:** share-of-voice percentage, competitor comparison data, and trend over the measurement history.

---

### 7. `get_citation_sources(url)`

Returns the third-party domains AI engines cited when answering buyer questions in the given domain's category, and whether the given domain already appears on each source. These are the sites you need to get listed on to earn more AI citations.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain whose category to query |

**Returns:** list of cited source domains with citation frequency, and a presence flag indicating whether your domain is already mentioned on each source.

---

### 8. `get_fix_plan(url)`

Returns the prioritised fix list from the latest deep scan, ordered by expected impact — the changes most likely to move your AI Readiness Score appear first. Each item includes a plain-language description and the evidence behind it.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query |

**Returns:** ordered array of fix items, each with a title, description, supporting evidence, and whether the fix can be applied on-page or requires off-site action.

---

### 9. `get_mentions(url)`

Returns new pages on the web that mention the given domain, found in the daily web sweep. Pass an optional `days` parameter to control the look-back window.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to monitor for mentions |
| `days` | integer _(optional)_ | Number of days to look back (default: 7) |

**Returns:** list of pages mentioning the domain, each with URL, title, publication date, and snippet.

---

### 10. `get_benchmark(url)`

Returns the given domain's rank and percentile against every other measured business in its category. Use this to see whether a score of, say, 45 is strong or weak for your market.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to benchmark |

**Returns:** category name, rank, percentile, category median score, and the number of businesses in the comparison set.

---

### 11. `get_ai_traffic(url)`

Returns the visitors AI engines actually sent to the given domain over the last 30 days, recorded by the site's own AI-traffic beacon — broken down by engine and week.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query (must have the traffic beacon installed) |

**Returns:** total AI-referred visits and a per-engine, per-week breakdown covering ChatGPT, Perplexity, Claude, Gemini, and Copilot.

---

### 12. `get_agent_view(url)`

Returns how a headless agent browser renders the given domain: whether the page renders fully, partially, or blank, how many characters of content an agent can actually extract, and what is blocking full extraction if anything is.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to check |

**Returns:** render status (full / partial / blank), extractable character count, and recommendations for improving agent-readability.

<Note>
  `get_agent_view` refreshes daily on the scheduled crawl, not immediately after a `request_rescan`. Do not use it to verify a change you deployed today — check it the following day.
</Note>

---

### 13. `get_personas(url)`

Returns the buyer personas behind the tracked buyer questions for the given domain. Each persona includes a name, description, and the specific questions that persona is mapped to.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to query |

**Returns:** array of buyer personas with mapped questions for each.

---

### 14. `get_post_brief(url)`

Returns a drafting brief assembled from this week's verified measurement data: fresh mentions, the buyer questions where the domain is absent, and the citation sources the engines read in its category. Hand this to your AI assistant to draft content in your own voice, grounded in real measurement rather than guesswork.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to build the brief for |

**Returns:** a structured content brief with current gaps, source targets, and suggested angles — all drawn from live measurement data.

---

### 15. `get_context()`

Returns the complete weekly context document for your monitored domain: current scores, every tracked buyer question with its verbatim answer status, new mentions, the citation game plan and what to do next. It is the same content as the downloadable `context.md`, so an assistant can load your whole position in one call at the start of a conversation.

| Parameter | Type | Description |
| --- | --- | --- |
| _(none)_ |  | The document is built for the domain behind the token in your endpoint URL |

**Returns:** one Markdown document covering scores, tracked questions and their trajectories, mentions, priority fixes, citation targets and connections.

---

### 16. `get_source_profile(domain)`

Returns a profile of any domain the answer engines cite: how often our measurements saw engines read it and across how many businesses and categories, what the site says it is from our crawl of its homepage, the other sources it is usually read alongside, and how to get listed or mentioned on it.

| Parameter | Type | Description |
| --- | --- | --- |
| `domain` | string | A cited source domain, for example one returned by `get_citation_sources` |

**Returns:** read frequency and breadth, the source's own description, its co-read pack, and the practical route onto it.

---

### 17. `request_rescan(url)`

Queues an immediate rescan of the given domain, consuming one on-demand scan credit from your plan's weekly allowance. The weekly scheduled scan runs regardless of this call and is not affected by the credit balance.

| Parameter | Type | Description |
|-----------|------|-------------|
| `url` | string | The domain to rescan |

**Returns:** confirmation that the rescan is queued, expected completion time, and the number of on-demand credits remaining this week.

<Warning>
  On-demand rescans are capped at 5 per rolling 7 days, with a 20-minute cooldown between consecutive calls. If the server refuses a rescan, wait for the cooldown or the next weekly scheduled scan rather than retrying. Never call `request_rescan` again while polling for results from a rescan already in progress.
</Warning>

## Fleet plan tools

If you are on the Fleet plan, seven additional tools let you query across your entire client network:

| Tool | Description |
|------|-------------|
| `get_network_summary()` | Portfolio-wide AI Visibility and Readiness scores across all sites in your network |
| `list_sites()` | Every site in the network with its latest visibility and readiness, week movement, verdict and monitoring status, worst performers first |
| `get_site_scores(domain)` | Visibility and readiness scores for a specific site in your fleet |
| `get_site_mentions(domain)` | Recent web mentions for a specific site in your fleet |
| `get_site_fix_plan(domain)` | Prioritised fix list for a specific site in your fleet |
| `get_site_personas(domain)` | The buyer personas measured and edited for one site: who its buyers are, what each is trying to do, and the questions that persona asks. Cards a human pinned or wrote are marked |
| `get_site_post_brief(domain)` | Content brief for a specific site in your fleet |

Per-staff keys are scoped and revocable — issue a scoped key to give a client or agent access to their own site data without exposing your full fleet token.

## Example prompts once connected

After adding the MCP server to your AI assistant, ask questions like these in plain language:

```text
@found-by-ai What is my current AI visibility score for example.com?
@found-by-ai Show me the verbatim answers ChatGPT gives when buyers ask about my category.
@found-by-ai What should I fix first to improve my AI readiness score?
@found-by-ai Which competitors is AI naming instead of me, and on which questions?
@found-by-ai Which third-party sites do the engines cite in my market, and am I on them?
```

Your assistant translates each natural-language question into the appropriate tool call and returns a plain-English answer drawn from your live measurement data.

## Tool permissions at a glance

- **Read-only tools** (`get_visibility`, `get_answers`, `get_cited_queries`, `get_question_trajectories`, `get_rivals`, `get_share_of_voice`, `get_citation_sources`, `get_fix_plan`, `get_mentions`, `get_benchmark`, `get_ai_traffic`, `get_agent_view`, `get_personas`, `get_post_brief`, `get_context`, `get_source_profile`): work with both personal tokens and scoped keys.
- **Action** (`request_rescan`): requires a full personal or fleet token — scoped keys cannot trigger new measurements.

The MCP connection can never modify your account, change your plan, or access your billing details. The only side-effect available is queuing a rescan of your own domain, within your plan's stated cap.
