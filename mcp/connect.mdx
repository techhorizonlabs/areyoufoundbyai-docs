There are two ways to give your AI assistant your Are you found by AI? data. An **MCP connection** lets the assistant query your measurements mid-conversation, whenever the question comes up. A **standing instruction** tells the assistant to fetch your live console data at the start of every new chat. Use MCP where your client supports it (the Claude app, Claude Code, Cursor and other MCP clients), and the standing instruction for Claude Projects, ChatGPT Projects, Perplexity Spaces and Gemini Gems.

Your console's **Connect your AI** section has all of this pre-filled with your token, with one-tap copy buttons.

<Note>
  **No account yet?** Use the demo endpoint (`https://areyoufoundbyai.com/mcp/demo`) to test the connection against our own live monitoring of areyoufoundbyai.com. It needs no key and no signup. In Claude Code:

  ```bash
  claude mcp add --transport http found-by-ai https://areyoufoundbyai.com/mcp/demo
  ```
</Note>

## Your endpoint

Each monitored site has its own token. The recommended form is the static endpoint `https://areyoufoundbyai.com/mcp` with the token in a header, either `Authorization: Bearer YOUR-TOKEN` or `x-api-key: YOUR-TOKEN`. URLs end up in server logs, proxies and browser history, and headers do not.

Many clients only take a URL. For those, the path form keeps working:

```text
https://areyoufoundbyai.com/mcp/YOUR-TOKEN
```

Both forms reach the same tools.

## Connect over MCP

<Tabs>
  <Tab title="Claude app">
    <Steps>
      <Step title="Open Connectors">
        In the Claude app, open **Settings**, then **Connectors**, then **Add custom connector**.
      </Step>
      <Step title="Paste your endpoint">
        Paste your endpoint URL (`https://areyoufoundbyai.com/mcp/YOUR-TOKEN`, or the demo URL to try it first) and save.
      </Step>
      <Step title="Test the connection">
        Start a new chat and ask:

        ```text
        What moved in my AI visibility this week?
        ```

        Claude queries your measurements live and answers from this week's data.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Claude Code">
    <Steps>
      <Step title="Add the server">
        In a terminal, run:

        ```bash
        claude mcp add --transport http found-by-ai https://areyoufoundbyai.com/mcp/YOUR-TOKEN
        ```

        Replace `YOUR-TOKEN` with your token, or use `demo` to try the public demo.
      </Step>
      <Step title="Test the connection">
        Start a Claude Code session and ask:

        ```text
        How visible is this business to AI, and what would you fix first?
        ```
      </Step>
    </Steps>

    <Tip>
      If a coding agent builds your site, it can read your fix plan over this same connection, apply the fixes in your repository with your approval, and re-measure.
    </Tip>
  </Tab>

  <Tab title="Cursor">
    Add a custom MCP server with HTTP transport and use your endpoint URL. Or use the one-click **Add to Cursor** link in your console's **Connect your AI** section, which fills in the configuration for you.

    ```text
    https://areyoufoundbyai.com/mcp/YOUR-TOKEN
    ```
  </Tab>

  <Tab title="Other MCP clients">
    Add a custom server with HTTP transport and the endpoint above. If the client lets you set request headers, use the static endpoint `https://areyoufoundbyai.com/mcp` with an `Authorization: Bearer` or `x-api-key` header. Otherwise use the path form.
  </Tab>
</Tabs>

## Use a standing instruction

Claude Projects, ChatGPT Projects, Perplexity Spaces and Gemini Gems let you set persistent instructions that apply to every new conversation inside them. Your console link is a live URL, not a snapshot: fetched today it returns today's data, and fetched again in six weeks it returns the data then. Point your AI at it once and every new chat starts current.

Paste this, replacing `YOUR-TOKEN` with your token:

```text
At the start of every new conversation in this project, fetch https://areyoufoundbyai.com/monitor/YOUR-TOKEN.json (or the plain-text version at https://areyoufoundbyai.com/monitor/YOUR-TOKEN/context.md) and use it as my current Found by AI data, my AI-visibility score, tracked buyer questions, priority fixes and citation targets, before answering anything about my AI visibility, competitors, or what to do next. Re-fetch it fresh every new chat; don't rely on a cached copy from an earlier conversation.
```

<Tabs>
  <Tab title="Claude Projects">
    Create or open a Project, find its custom instructions or project knowledge setting, and paste the text above. Every new chat inside that project starts with your latest data.
  </Tab>

  <Tab title="ChatGPT Projects">
    Open a Project and paste the text above into its instructions field; it applies to every new chat you start there.

    If you are building a custom GPT and want it to query your data on demand mid-conversation, rather than only at the start, that needs an Action wired to the JSON endpoint. That is more setup; ask us if you want a hand.
  </Tab>

  <Tab title="Perplexity Spaces">
    Spaces support custom instructions the same way. Add yours to a Space dedicated to your business.
  </Tab>

  <Tab title="Gemini Gems">
    Gems support a persistent instructions field. Create a Gem for this and paste the text above.
  </Tab>
</Tabs>

Exact menu labels move around as these products update. Look for "instructions", "custom instructions" or "project knowledge" inside whatever the tool calls a Project, Space or Gem. The text you paste is the part that matters.

## Verifying the connection

For an MCP connection, ask a question that needs a live tool call:

```text
What is my current AI visibility score, and what changed since last week?
```

A working connection answers with numbers from your latest measurement. If your assistant gives a generic answer about AI visibility, the server is not connected yet: revisit the setup steps and check the endpoint.

You can also ask:

```text
List the MCP tools you can call on the found-by-ai server.
```

A connected assistant lists 20 tools on the demo (19 read tools and `request_rescan`), or 23 with your own token, which adds `get_balance`, `get_weekly_brief` and `get_grants`. If it cannot list them, the server has not been registered.

<Warning>
  Keep your token private. Anyone who holds it can read your measurement data. Never paste it into a public document, a shared page or a public GitHub repository. Sharing it with your own AI assistant, or a teammate you trust, is what it is for.
</Warning>

## Troubleshooting

<Accordion title="My assistant answers from its training knowledge instead of calling the MCP server">
  The server registration probably did not complete. In Claude Code, run the `claude mcp add` command again. In the Claude app, check the connector under **Settings**, then **Connectors**. For other clients, confirm the saved endpoint is correct: with the path form, check that `/mcp/YOUR-TOKEN` is present and that you replaced `YOUR-TOKEN` with your actual token; with a header, check the header name and value.
</Accordion>

<Accordion title="The connection works but returns no data">
  The tools answer for the site behind your token, from its saved measurements. If that site has not been measured yet, run the free scan at [areyoufoundbyai.com](https://areyoufoundbyai.com) first, then ask again.
</Accordion>

<Accordion title="I want to test without creating an account">
  Use the demo endpoint:

  ```text
  https://areyoufoundbyai.com/mcp/demo
  ```

  It is connected to our own live monitoring of areyoufoundbyai.com and carries all 20 tools. On the demo, `request_rescan` returns a worked example without queuing anything. It needs no key and no signup.
</Accordion>
